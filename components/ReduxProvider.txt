
// ============================================================
// HOW PROVIDER AND STORE INTERACT: 
// ============================================================
//
// 1. store is created in store.ts with configureStore
//    → holds { auth: { user: null, loading: true, modalOpen: false } }
//
// 2. store is passed to <Provider store={store}>
//    → Provider puts the store into React context
//    → every child component can now access it
//
// 3. AuthListener runs onAuthStateChanged inside useEffect
//    → Firebase checks if a user is already logged in
//    → if yes: store.dispatch(setUser(...)) → user = { uid, email }
//    → if no:  store.dispatch(clearUser()) → user = null
//
// 4. Any component using useAppSelector reads from the store
//    → state.auth.user → gets the current user value
//    → state.auth.modalOpen → gets whether modal is open
//
// 5. Any component using useAppDispatch sends actions to the store
//    → dispatch(openModal()) → store updates → AuthModal re-renders
//    → dispatch(setUser(...)) → store updates → any component reading user re-renders
//
// ============================================================
// FLOW WHEN USER LOGS IN:
// ============================================================
//
// User submits login form in AuthModal
//      ↓
// Firebase authenticates the user
//      ↓
// onAuthStateChanged fires with firebaseUser object
//      ↓
// store.dispatch(setUser({ uid, email }))
//      ↓
// Redux state updates: user = { uid, email }
//      ↓
// useAppSelector in BookDetailPage gets new user value
//      ↓
// !user = false → clicking Read/Listen now navigates instead of opening modal
//
// ============================================================
// WHEN USER LOGS OUT:
// ============================================================
//
// User logs out
//      ↓
// onAuthStateChanged fires with null
//      ↓
// store.dispatch(clearUser())
//      ↓
// Redux state updates: user = null
//      ↓
// !user = true → clicking Read/Listen opens modal again
// ============================================================


# Project Notes

## File 1 — `ReduxProvider` + `AuthListener`

### Purpose
Wraps the entire app with the Redux store and keeps Firebase auth in sync with Redux state.

### `"use client"` — Why It's Required
- Next.js App Router makes all components **Server Components by default**
- Server Components **cannot** use React context, hooks, or browser APIs
- `Provider` uses React context under the hood
- `useEffect` (used in `AuthListener`) is a React hook — client only
- Without `"use client"` this file crashes on the server

---

### Key Imports

| Import | From | Purpose |
|--------|------|---------|
| `Provider` | `react-redux` | Makes the Redux store available to all children via context |
| `store` | `@/lib/store` | The configured Redux store holding `{ auth: { user, loading, modalOpen } }` |
| `useEffect` | `react` | Runs the Firebase listener once on mount |
| `onAuthStateChanged` | `firebase/auth` | Listens for login/logout events from Firebase |
| `auth` | `@/lib/firebase` | The initialized Firebase Auth instance |
| `setUser` | `@/lib/slices/authSlice` | Dispatched when a user is detected — sets `user = { uid, email }` |
| `clearUser` | `@/lib/slices/authSlice` | Dispatched when no user — sets `user = null` |

---

### `AuthListener` Component

**Why it's a separate component:**
- It needs access to the Redux store via `Provider`
- If it were *outside* `Provider`, it could not dispatch actions
- Keeps code clean and separation of concerns clear

**What it does:**

```
onAuthStateChanged(auth, (firebaseUser) => {
  if (firebaseUser) → dispatch(setUser({ uid, email }))
  else             → dispatch(clearUser())
})
```

**Cleanup / Memory Leak Prevention:**
- `useEffect` returns `() => unsubscribe()`
- This stops the Firebase listener when the component unmounts
- Without it: listener keeps running in the background → memory leak → potential errors

**`return <>{children}</>`:**
1. React requires every component to return something
2. Passes children through so the rest of the app renders on screen

---

### `ReduxProvider` Component

```
<Provider store={store}>        ← makes store accessible everywhere
  <AuthListener>                ← listens for auth changes, must be INSIDE Provider
    {children}                  ← the rest of your app
  </AuthListener>
</Provider>
```

## File 2 — `BookDetailPage`

### Purpose
Displays book details and protects the Read/Listen actions behind authentication.

---

### Key Additions (Auth Protection)

**Step 1 — New Imports:**
```ts
import { useAppDispatch, useAppSelector } from "@/lib/hooks";
import { openModal } from "@/lib/slices/authSlice";
import { useRouter } from "next/navigation";
```

**Step 2 — New State:**
```ts
const dispatch = useAppDispatch();
const user = useAppSelector((state) => state.auth.user);
const router = useRouter();
```

**Step 3 — Protected Action Handler:**
```ts
const handleProtectedAction = (destination: string) => {
  if (!user) {
    dispatch(openModal());     // no user → open login modal
  } else {
    router.push(destination);  // logged in → navigate
  }
};
```

**Step 4 — Applied to Buttons:**
```tsx
<button onClick={() => handleProtectedAction(`/player/${id}`)}>Read</button>
<button onClick={() => handleProtectedAction(`/player/${id}`)}>Listen</button>
```

---

### Skeleton Loader (`BookDetailSkeleton`)

- Shown while `loading === true`
- Uses a shimmer CSS animation (`linear-gradient` + `backgroundSize: "200% 100%"`)
- Mimics the layout of the real content (title, author, stats, buttons, image)
- Prevents layout shift while data loads

---

### Auth Flow on This Page

```
User clicks Read/Listen
        ↓
handleProtectedAction runs
        ↓
user === null?
  YES → dispatch(openModal()) → login modal appears
  NO  → router.push(`/player/${id}`) → navigates to player
```

## Global Auth Flow (Both Files Together)

```
App loads
  → ReduxProvider mounts
  → AuthListener starts onAuthStateChanged
  → Firebase checks if user is logged in
      → YES: dispatch(setUser) → state.auth.user = { uid, email }
      → NO:  dispatch(clearUser) → state.auth.user = null

User visits BookDetailPage
  → useAppSelector reads state.auth.user
  → Clicks Read/Listen
      → if null  → openModal()
      → if user  → navigate to /player/[id]

User logs in via modal
  → Firebase fires onAuthStateChanged
  → dispatch(setUser) → state updates
  → BookDetailPage re-renders, user is now set
  → Next click navigates directly
```
